## Decision

**Not ready to accept.** The platform is much closer to one product than on Day 3: a real scan of the vulnerable demo repo goes `QUEUED → COMPLETED` with 37 findings, 4 SBOM and 18 CBOM components, organization isolation holds, data survives a full restart, and the desktop app builds unpatched and only talks to `127.0.0.1:8000`. But four groups of problems block acceptance:

1. **A clean install doesn't start.** `backend/app/core/security.py:7` imports `BcryptHasher`, but both requirements files only install `pwdlib[argon2]`. Found independently by four agents. Fix: `pwdlib[argon2,bcrypt]` in `requirements.txt` and `backend/requirements.txt`. Owner: Amrutha (introduced in `6123b9b`).
2. **Known credentials work in production.**
   - The JWT secret in `.env.example` is accepted with `APP_ENV=production`, and the README says to copy that file. The agent forged an admin token with it and it worked.
   - The seeded admin `admin@pqc.example` / `change_me_locally` logs in on every install, and nothing forces a change.
   - Everyone who registers is put into the admin's organization (BE-19, still open).

   Owners: Amrutha (config, registration), Vamsi / Viswanath (seed, `.env.example`).
3. **The demo path in the desktop app breaks.**
   - Findings search white-screens the app: `Findings.tsx:134-139` calls `f.id` / `f.file`, but the API sends `finding_id` / `file_path`, and there's no error boundary.
   - The ID, file and line columns are blank.
   - There's no sign-out.
   - Totals silently cap at 100 findings.

   The fixes already exist on `hema-findss` and `PQC-frontend` but aren't merged. Owners: Hema, Harshith, Viswanath.
4. **The process isn't followed.** None of the 22 commits on `integration` since 30 Sep came through a merged PR; there's one open PR (#3) with no review. `integration` and `main` are unprotected in a public repo, and Dependabot, secret scanning and CI are all off. Owner: Viswanath.

**Act now:** `database/DATABASE_README.md:115-117, 511` uses `Vsvg@mysql` as its "example" password (Vamsi, `b8ce268`). If that's a real password anywhere, change it. The repo is public and the value is in the history.

## What held up

- **Organization isolation:** every cross-organization read and cancel returns 404. Findings, reports and `scan_id` filtering are fixed (BE-20, INT-35).
- **Authentication:** `none`, tampered, expired and wrong-key tokens are all refused.
- **Error hygiene:** 72 hostile requests gave no tracebacks, SQL, paths or echoed passwords.
- **CORS:** a strict allowlist.
- **Uploads:** capped at 200 MB.
- **Pipeline:** status transitions are truthful, with per-engine status. Three scans of the same repo gave identical findings, SBOM and CBOM (**determinism passes**). The same job queued 4 times ran once. Corrupt ZIPs, zip bombs (3 GB, 150,000 files), zip-slip and symlinks all end `FAILED` with the workspace removed. Cancel while `QUEUED` or `ANALYZING` works, and a double cancel gives 409. INT-30 to INT-35 and INT-37/38 are fixed, and the ReDoS hang is gone (400 KB lines finish in 0.3 s). Scanned code never runs, fake secrets are redacted (except AWS key IDs), and the only network traffic is to local MySQL and Redis.
- **Persistence:** after a full MySQL, API and worker restart, every row and API response was identical. Queries use the right indexes up to 300,000 findings. Models match the live schema. `verify_db.py` and the combined-flow script are idempotent.
- **Desktop:**
  - It builds unpatched and makes network calls only to `127.0.0.1:8000`.
  - Its CSP and capabilities are strict, and an XSS payload rendered as text.
  - Mock data files are gone, and PDF/CSV export is labelled as planned.
  - `npm audit --omit=dev` and `cargo audit` are clean.
- **Repo:**
  - No real secrets in history, apart from item 10.
  - No committed `.env`, `.db`, ZIP, `.pyc` or build output.
  - No `eval`, `subprocess` or outbound network code.
  - `pip-audit` is clean.
  - The root `.gitignore` works.
